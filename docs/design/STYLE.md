# Claude 控制中心（Agent Board）— 設計邏輯與風格「塔台 × 放手線」

> 適用：`packages/web` 的所有畫面。
> 可以直接打開看的範例：同資料夾 `style-sample.html`（單一檔、零外部套件）。Token 實作：`packages/web/src/shared/styles/tokens.css`。
> 基底是一套高對比深色規範，本文件已列出實作需要的差異；背景、文字、控制項高度、字級、間距、圓角、陰影的數值都是 `tokens.css` 的 token（2026-11-09 補齊），按鈕、輸入框等共用元件的樣式在 `packages/web/src/shared/styles/controls.css`，規則見 §5「控制項尺寸與層級」。

---

## 0. 一句話

**這是一座塔台：你不是在看十個終端機，你是在決定下一個該處理誰。最大的數字永遠是「幾個在等你」；顏色只回答「球在誰手上」；每張卡左邊的線型回答「你放手了多少」；終端機裡面的顏色是 Claude Code 的，我們一筆都不碰。**

兄弟介面各自要防的東西：

| 介面 | 要防的 | 主角 |
|---|---|---|
| 海龜訊號 | 虧錢、誤下單 | 帳戶權益 |
| 策略驗證平台 | 自欺 | 通過關卡的策略數 |
| tw-quant | 把未驗證的訊號當依據 | 已放行策略數 |
| 美股量化平台 | 偷看未來資料 | 通過 G1–G6 的策略數 |
| 外匯模組 | 以為分散了其實全押同一貨幣 | 開倉許可 |
| 加密市場控制台 | 把不同可信度的數字混在一起 | 每頁標段與證據等級 |
| **Claude 控制中心** | **agent 停下來等你而你不知道；在看錯 session 的情況下按了「允許」** | **等你的數量** |

和其他專案最大的差別：這裡的畫面中央放的是**別人的介面**（Claude Code 的 CLI 原始輸出），我們的外框不能和它搶。

## 1. 四條專屬規則（這次的創新）

### 規則一：顏色只回答「球在誰手上」— 用狀態代碼說

一眼掃過畫布，只需要知道每個 session 現在該誰動。**GM 2026-11-08 改版**：剛開好、還沒下指令的 session 和真的在等回覆的原本都標黃，畫面一片黃。現在每張卡、每個徽章都顯示一個**英文狀態代碼**，一個代碼一個顏色，色相拉開；完整中文說明放在提示框（`title`）與 `aria-label`，側欄圖例寫「代碼＋中文」。代碼的判斷只有一處：`packages/web/src/shared/status.ts` 的 `statusCode(session)`（要用 `statusDetail`）。

| 代碼 | 對應的 session 狀態 | 顏色（`tokens.css` 的 `--c-<code>`） | 算不算「等你」 |
|---|---|---|---|
| **NEW** | `starting`，或 `waiting_input` 且 `statusDetail = 'idle:start'`（剛開好、還沒下指令），或 `waiting_input` 且 `awaiting` 有值（派工：「等隊長」／「等成員結果」，GM 2026-11-11） | 灰 `#9aa4b2` | 否 |
| **RUN** | `running` | 藍 `#4aa3ff` | 否 |
| **ASK** | `waiting_input`（不是 idle:start、不是等隊長／等成員結果；重新接回的 `resume` 也算） | 黃 `#ffe14d` | 是 |
| **PERM** | `waiting_permission`（含命中危險指令，徽章用 ⛔） | 洋紅 `#ff4fd8` | 是，最急 |
| **PLAN** | `plan_review` | 青 `#3dd5e0` | 是 |
| **ERR** | `error` 與 `stuck`（提示框分辨是錯誤還是卡住，符號 ✕／⚠） | 紅 `#f0665f` | 是 |
| **QUOTA** | `rate_limited` | 紫 `#9b6bff` | 否 |
| **QUE** | `queued` | 棕 `#d4a373` | 否 |
| **DONE** | `done`（session 已結束；偵測不到「等你驗收」，先併進 ASK） | 綠 `#46c26a` | 否 |
| **OFF** | `offline` | 深灰 `#6e7681`，卡片虛線框＋斜紋（規則四） | 否 |

- **「等你」只算 ASK、PERM、PLAN、ERR**：頁首計數、「下一個等我的」、收件匣、審核中心都一樣（和 protocol `attention.ts` 的 `sessionWaitsForUser` 同一個定義）。「下一個等我的」、收件匣、審核中心的順序：⛔ 命中危險指令置頂 → ERR → PERM → PLAN／ASK，同級等最久的在前。待處理頁（`#/queue`）另依組別分組（要你決定 → 等你回覆 → 出問題 → 其他，GM 2026-11-06，`flows/triage.ts`），組內才照等待時間。
- **卡片**：邊框、標題色帶（上緣 4px＋淡底）、呼吸光圈都用代碼色（GM：邊框跟代碼同色）。手機收件匣的卡也一樣用代碼色 `--sc`（2026-11-09 審視時手機收件匣卡仍是琥珀框，是程式違反這條，待收件匣區修正）。算「等你」的四種 2px 框＋呼吸光圈，其他 1px、不呼吸。OFF 虛線框＋斜紋。樣式：`shared/styles/status.css` 的 `.c-<code>`（設 `--sc`），卡片在 `canvas/canvas.css`、`canvas/expanded.css`。
- **徽章**：實心代碼色、深色字（OFF 用淺色字），代碼是主要文字（等寬粗體），前面保留符號。清單裡不是徽章的狀態燈：符號＋代碼用代碼色，後面接一段淡色說明。
- **每個代碼都有符號與文字**，不只靠顏色。
- 藍色是語意色，所以母規範拿藍色表示的「選中、主按鈕、焦點」改成**白色**（同美股、外匯）。全站強調色維持白色，狀態色只用在狀態。
- **綠色只有兩個地方**（取消原本「整個介面沒有綠色」）：DONE 狀態代碼（徽章、狀態燈、DONE 卡的框與色帶），以及審核中心的 diff 區塊（`--diff-add` `--diff-del`，一定配 `+` `−`）。「上線」仍用白點。
- 「額度」相關一律用 QUOTA 的紫色（`--quota` 同 `--c-quota`）：額度用量條 ≥ 85% 時、耗額度晶片（規則三之二）。
- 原本的組別色（`--you` 琥珀、`--fault` 紅、`--agent` 藍、`--idle` 灰）只留給不是狀態的提示（頁首「等你」、用量條、危險按鈕等），不再畫在卡片上。

**代碼色的 WCAG 對比（2026-11-08 實測，公式同下；色盲 ΔE 未測）**：
- 實心徽章，深色字 `--on-solid #14100a`：NEW 7.51、RUN 7.20、ASK 14.55、PERM 6.64、PLAN 10.64、ERR 6.11、QUOTA 5.36、QUE 8.38、DONE 8.29；OFF 用白字 `--fg` 4.59。全部 ≥ 4.5:1。
- 不是徽章的狀態燈（代碼色字在 `--surface #14181f` 上）：NEW 7.06、RUN 6.76、ASK 13.67、PERM 6.24、PLAN 9.99、ERR 5.74、QUOTA 5.03、QUE 7.87、DONE 7.78。OFF 原色只有 3.87，字改用 `color-mix(in srgb, var(--c-off) 70%, var(--fg))`（`#9a9fa7`，6.69）；卡片框線仍用原色 `#6e7681`。

**實測（2026-11-06 的組別色，代碼色的色盲 ΔE 尚未重測）**（WCAG 對比以 `--surface #14181f` 為底；ΔE76 用 Machado 2009 severity 1.0 模擬）

| 配對 | 正常 | 紅色盲 deutan | 綠色盲 protan | 藍色盲 tritan |
|---|---|---|---|---|
| agent ↔ you | 119.9 | 123.6 | 116.0 | 76.8 |
| agent ↔ fault | 98.0 | 93.6 | 70.2 | 111.5 |
| agent ↔ quota | 50.3 | 32.9 | **12.5** | 72.9 |
| you ↔ fault | 55.7 | 32.5 | 51.6 | 38.8 |
| you ↔ quota | 100.9 | 91.3 | 103.7 | **17.4** |
| fault ↔ quota | 60.9 | 62.2 | 57.7 | 41.9 |

對比：agent 6.76、you 9.57、fault 5.74、quota 7.71、idle 11.53，全部 ≥ 4.5:1。
**選色經過**：第一版額度用紫 `#a68bff`，和藍色在紅色盲下 ΔE 只有 2.8，幾乎分不開，改成洋紅。最差的 12.5 仍偏低，靠符號（● vs ⧖）當第二編碼。（這是 2026-11-06 組別色的紀錄；2026-11-08 改成代碼色後，洋紅給了 PERM，額度 `--quota` 回到紫 `#9b6bff`，見規則一的表。）

### 規則二：放手線 — 左邊的線型回答「你放手了多少」

看錯權限模式就像海龜看錯模擬盤和實盤。每張卡左邊一條線，線越實，agent 越能不問你就動手。用線型不用顏色（延伸加密控制台的「越接近錢，線越實」）：

| 線型 | 模式 | 官方文件：不經詢問會執行什麼 |
|---|---|---|
| 點線 3px | `plan`、`dontAsk` | plan：只讀（auto 可用時加上分類器核可的指令）。dontAsk：只有事先允許的，**其餘自動拒絕** |
| 虛線 3px | `default` | 只讀，其他每步問你 |
| 實線 3px | `acceptEdits` | 讀、改檔、常見檔案指令 |
| 實線 5px | `auto` | 全部，有背景安全檢查 |
| **實線 5px、紅色** | `bypassPermissions` | **全部，不檢查** |

- 線旁邊一定有模式晶片，寫出模式名稱。
- `bypassPermissions` 等同海龜的「實盤」：紅線＋紅框晶片「略過權限」，在卡片、審核卡、新增 session 預覽都看得到。**這是紅色唯一不代表故障的地方，但它同樣表示要小心。**

### 規則三：終端機是別人的；會花額度的按鈕要自己說

**三之一：終端機裡面不碰。** 派工單的核心原則是畫面和原生 CLI 一模一樣。
- 狀態、按鈕、徽章一律在 xterm **外框之外**，絕不疊在終端機內容上。
- xterm 主題背景用 `--term-bg`（等於 `--bg`），16 色 ANSI 用 xterm 預設，不套品牌色。
- 摘要卡的「最後 4 行」是**去除 ANSI 的純文字**，用 `--fg-muted` 等寬字：縮小時不該有一片花色和狀態燈搶注意力。

**三之二：耗額度要標。** 中控台本身不花額度，所以少數會讓 session 花額度、又不像是在下指令的按鈕，要自己講：**◈ 耗額度**（紫色晶片，`--quota`，同 QUOTA 代碼色）貼在按鈕旁。目前有：「請隊長拆解」、開啟自動交接規則。

### 規則四：看不到的就是看不到

- **機器失聯**：卡片凍結在最後畫面，整張 45% 淡化＋灰色斜紋，寫「⊘ 失聯・最後讀到 HH:MM」。不把舊資料當現況（母規範的資料過期，縮小到單張卡）。
- **判斷不出來就寫工作中**（派工單 §4）：不用任何燈號表達猜測。
- **每張卡都有時間**：等你的卡寫「等了 12 分」，工作中的卡寫「3 秒前有輸出」。超過 10 分鐘沒輸出自然變成 ⚠ 卡住。

## 2. 設計邏輯（為什麼長這樣）

| # | 邏輯 | 畫面上的做法 |
|---|---|---|
| 1 | **一個主角：等你幾個** | 頁首固定「等你 3」26px（`--fs-hero`）＋主按鈕「下一個等我的 N」。其他數字都比它小。0 個時寫「沒有等你的」，不留空 |
| 2 | **按「允許」之前先確認呼號** | 審核卡最上方永遠是呼號 `機器 / 專案 @ 分支`（等寬）＋模式晶片＋放手線，再來才是工具與 diff。手機同樣，不省略 |
| 3 | **等最久的排最前** | 「下一個等我的」、收件匣、審核中心的順序：⛔ 命中危險指令 → ERR（✕ ⚠ 故障）→ PERM（◆）→ PLAN／ASK（▣ ◇）依等待時間由久到短；NEW 不算。待處理頁依組別分組（決定 → 回覆 → 出問題 → 其他），組內照等待時間 |
| 4 | **縮放是語意的** | 畫布縮放 < 90%：摘要條；≥ 90% 或點兩下：真的 xterm。兩者同一個外框、同一個位置，不跳動 |
| 5 | **靜止時要安靜** | 全部工作中的畫布應該幾乎沒有亮色。亮度留給要你處理的東西：算「等你」的卡（ASK、PERM、PLAN、ERR）2px 代碼色框＋呼吸光圈，其他 1px 代碼色框 |
| 6 | **危險操作要多一道** | 允許命中危險清單的指令：按兩次（第一次顯示指令全文）。拒絕、要求修改：原因必填。全隊停止：按兩次（之後的「全隊啟動」只用 `--resume` 接回、不送字，按一次）。不用原生 confirm |
| 7 | **一切留痕** | 送入終端機的指令與核准／拒絕都進 audit_log；操作結果 `.msg` 緊貼按鈕 |
| 8 | **四種狀態都有畫面** | 載入中、空的（寫下一步：「按『新增 session』開始」）、錯誤、資料過期（hub 連不上時整頁淡化＋一行字，內容凍結） |

## 3. 資訊架構

```
頁首（sticky、半透明＋8px 模糊）
  Agent Board   [等你 3] [下一個等我的 N]   … [中｜EN] [搜尋] [收件匣 N] [⚙]
  工作區分頁：主要 ｜ 美股 ｜ ▾AI專案［…］ ｜ ▸伺服器 2 ｜ … ｜ +   ← 選中＝白色 2px 底線；群組可收合，放不下左右捲（CONTRACTS §25）
底部指令列（桌面）：＋新增 session ｜ 群組 ｜ Presets ｜ Memory ｜ 全部暫停 ｜ 全部繼續
  （頁首的「新增 session」只在手機或沒有指令列時出現）
主區（畫布滿版，不套 1320px 上限；其他分頁主內容最寬 1320px）
  左側欄 232px，可收合：機器（上線／失聯、CPU／RAM／GPU）→ 額度 → 狀態圖例
  畫布：航班條、團隊框、交接虛線、便利貼；右下小地圖與縮放
手機（≤ 640px）：只有收件匣，只列等你的項目；複雜操作寫「回電腦處理」
```

骨架：母規範的**頂部分頁型**，畫布例外滿版。

## 4. 色彩

背景、表面、文字、邊框照母規範；間距、圓角、字級、控制項高度、陰影是 `tokens.css` 的 token（見 §5「控制項尺寸與層級」）。色彩只寫差異：

| Token | 色碼 | 用途 |
|---|---|---|
| `--accent` | `#ffffff` | 選中底線、主按鈕底；**不是藍色**。白色實心只給主按鈕（GM 2026-11-09 Q2：「下一個等我的」、表單送出、目前聚焦的那張卡）；遮蔽、交接規則「啟用」、側欄切換這類開關用「按下」樣式，不用實心白 |
| `--on-accent` | `#0a0c10` | 只用在白色主按鈕上的字 |
| `--accent-bg` | `rgba(255,255,255,.10)` | 選中的淡底 |
| `--ring` | `rgba(255,255,255,.6)` | 焦點外框 |
| `--you` | `#f2b33d` | 球在你手上 |
| `--fault` | `#f0665f` | 故障、`bypassPermissions`、危險按鈕 |
| `--agent` | `#4aa3ff` | 球在 agent 手上 |
| `--quota` | `#9b6bff` | 額度（同 QUOTA 代碼色，2026-11-08 起） |
| `--c-<code>` | 見規則一 | 狀態代碼色，只用在狀態 |
| `--idle` | `#c9d1d9` | 完成、失聯 |
| `--hatch` | 白 9% 斜紋 | 失聯、未開始 |
| `--diff-add` / `--diff-del` | `#46c26a` / `#f0665f` | diff 區塊，一定配 `+` `−`（綠另外只給 DONE） |
| `--term-bg` | `#0a0c10` | xterm 背景 |
| `--canvas-dot` | `#1b212b` | 畫布點陣 |

**團隊框色**（使用者選，避開狀態色）：青 `#3cc4b0`、萊姆 `#a8c957`、靛 `#8b93f5`、杏 `#e8a87c`，2026-11-06 加冰 `#75e5f0`、沙 `#f4ec9a`、梅 `#a8578f`、堇 `#7d5fc7`（id：teal、lime、indigo、apricot、ice、sand、plum、violet；資料庫存 id，不認得的當 teal）。一律 1px 框＋8% 底＋名稱標籤，不只靠顏色。介面只有深色主題，色碼只有一組。

實測（Machado 2009 severity 1.0，CIEDE2000／括號內 ΔE76；8 色兩兩取最小）：

| | 正常 | protan | deutan | tritan |
|---|---|---|---|---|
| 團隊色之間最小 | 14.4 萊姆/沙（21.6） | 10.6 梅/堇（17.6） | **5.5** 萊姆/杏（15.5） | 9.0 青/冰（13.5） |
| 團隊色對狀態色最小 | 14.0 靛/agent（19.0） | 2.6 靛/agent（3.9） | 1.5 靛/agent（5.7） | 2.6 杏/you（3.9） |

- 新增的 4 色沒有拉低原本 4 色的色盲下限（最差 5.5 是原本的萊姆/杏）。新色對狀態色在正常視覺下 ΔE00 都 ≥ 18.8（沙/you），對比 `--surface` ≥ 3:1（梅 3.75、堇 3.67，只用在框線與色塊，文字用 `--fg-muted`）。
- 團隊色對狀態色在色盲下會接近（最差是原本的靛和 agent 藍），所以團隊框一定配名稱標籤，狀態一定配符號。
- 選色方法：排除綠色與低彩度（和 idle 灰混淆），正常視覺對狀態色 ΔE00 ≥ 18、Lab 彩度 ≥ 30，再挑讓四種模擬下團隊色之間最小 ΔE 最大的。

**用量條**：CPU／RAM／GPU／context 用 `--agent`，≥ 60% `--you`，≥ 85% `--fault`。額度條用 `--quota`，≥ 85% 加 ⚠。

## 5. 專屬元件

| 元件 | class | 長相 | 設計理由 |
|---|---|---|---|

### 5.1 控制項尺寸與層級（GM 2026-11-09 Q1–Q3）

**原則**：桌面控制項只有兩級高度；手機有兩條下限；按鈕字級只用 13／14；「按下」只有一種樣子；白色實心只給主按鈕。數值一律用 `tokens.css` 的 token，各區 CSS 只調位置。舊寫法換新寫法的對照表：`docs/design/controls-migration.md`。

**尺寸**

| 尺寸 | class | 高 | 字級 | 左右內距 | 用在 |
|---|---|---|---|---|---|
| 標準（預設） | `button`、`a.button`、`.btn` | `--ctl-h` 36 | 14（`--fs-base`，沿用外層） | `--ctl-px` 14 | 頁首、表單、審核卡、對話框 |
| 精簡 | `.sm` | `--ctl-h-sm` 32 | `--fs-ctl-sm` 13 | `--ctl-px-sm` 10 | 卡片內、畫布浮動工具列、收件匣列動作、進度卡、列尾、篩選、關閉鈕、選單項目 |
| 觸控 | `.touch` | `--ctl-h-touch` 44 | 14 | 14 | 手機所有可點元素的下限（手機上全域自動套用） |
| 動作 | `.act` | `--ctl-h-thumb` 56（別名 `--ctl-h-act`） | `--fs-lg` 16 | 14 | 手機上會動到 session 的動作：允許、拒絕、暫停、繼續、送出回答 |
| 小標籤 | `--ctl-h-xs` | 24 | 12 | — | 只給畫布上反向縮放的小標籤（整理團隊、往來次數） |

- 同一列、同一張卡、同一條工具列只用一種尺寸。
- **手機斷點只有一個**：CSS `@media (max-width: 640px), (pointer: coarse)`，只寫在 `controls.css`；JS 版面切換用 `shared/breakpoints.ts` 的 `PHONE_QUERY`（`max-width: 640px`）。手機上 `button`、`a.button`、輸入框、下拉自動至少 44px，輸入框字級 16px（避免 iOS 聚焦放大；這條是 `font-size: max(16px, 1em) !important`，各區寫了 `font:` 也蓋不掉）。`.touch` 44／`.act` 56 也只在這個媒體查詢裡生效，桌面只有 36／32 兩級。畫布卡片內的控制項跟著畫布縮放，不套這條。

**層級**

| 層級 | class | 外觀 | 用在 |
|---|---|---|---|
| 主要 | `.primary` | `--accent` 白底、`--on-accent` 字 | 一個畫面原則上一顆：「下一個等我的」、表單送出、目前聚焦那張卡的處理鈕（Q2）。其他等你的卡的處理鈕用狀態代碼色框＋淡底（`button.cue`，`controls.css` 唯一一份；畫布卡片、收件匣列、手機收件匣共用），不用白色實心 |

| 危險 | `.danger` | `--fault` 12% 底＋紅框，hover 20%，焦點外框紅 | 刪除、全隊停止、拒絕（Q3：拒絕一律「填原因 → `.danger` 拒絕」，不是主按鈕） |

| 狀態 | 寫法 | 外觀 |

**其他共用元件**（都在 `controls.css`）：輸入框／下拉／textarea（預設 36px、`--surface-2` 底、`.sm` 32px）；核取與單選只設 `accent-color: var(--accent)`（選中是白，不是瀏覽器藍）；`label.check`；表單欄位 `.field`（標籤 13px／600／`--fg-muted`）；分段切換 `.seg`（相連、只有頭尾圓角，`.seg.sm` 32）；晶片 `.chip`（高 20、12px、`--radius-pill`）、`.chip.bypass`、`.chip.cost`；浮層選單 `.menu`＋`button.menu-item`（32，手機 44，說明 `.sub` 12px）；面板標題列 `.panel-head`（h1 18px／650，右側 `.panel-acts`）；空狀態 `.empty`（虛線框＋標題＋下一步）；一列控制項 `.row`。

**提問與拒絕（Q3）**：提問選項一律「先選（選中反白，用『按下』樣式）→ 按主按鈕送出」，桌面手機一致。拒絕一律「填原因 → `.danger` 拒絕」，三處同一套流程、同一層級：灰色「拒絕」→ 展開原因框（`flows/DenyForm.tsx`，收件匣列、手機、展開審核卡共用）→ 紅框「拒絕」＋「取消」。展開時「允許」那排收起：允許不會補到剛才拒絕的位置（連點兩下變允許），也不會同時有兩顆意思相反的紅鈕。

**畫布縮小（Q4）**：卡片在畫面上縮到約 30% 以下時，隱藏卡片上的按鈕與輸入框，只留標題列（狀態徽章、名稱、等待時間）；要處理時點兩下卡片或按「下一個等我的」。

### 5.2 浮動對話框（GM 2026-11-14）

**用在哪**：只給「建立型」的對話框——新增 session（`#/new`）、新增團隊、補成員、套用 Preset（底部「Presets」與團隊清單「從 Preset 建立」）。其他次畫面（設定、搜尋、封存、對話紀錄…）維持置中模態；封存、刪除這類確認框（`flows/Dialog.tsx`）維持擋住背後。共用元件 `views/FloatingDialog.tsx`（`ModalLayer` 的 `floating` 模式；哪些網址次畫面浮動看 `views/overlay.ts` 的 `FLOATING_MODALS`），不要每個頁面各寫一份拖曳。

- **不擋背後**：沒有暗化遮罩、背後不 inert、不鎖焦點（Tab 可以離開框）。開著時畫布照常看、點卡（＝選取）、捲動縮放；點畫布空白不會關框。會換網址的操作（點團隊框打開團隊面板、收件匣、卡片選單…）照網址規則換掉次畫面，新增 session／新增團隊的內容留在草稿（見下方）。開啟時焦點先進框；關掉時焦點還在框裡才還給原本的元素。
- **拖曳**：按住標題列（`.float-head`，`cursor: move`）拖，用 pointer events（滑鼠、觸控筆、觸控都可以），拖的時候不選字、觸控不捲頁。放開沒送到 pointerup（失去 pointer capture，或之後的 pointermove 已經沒有按鍵）也會結束拖曳。鍵盤：焦點在框裡、但不在可輸入的元素（input、textarea、select、contenteditable）時，Alt＋方向鍵移 16px（加 Shift 64px）；在輸入框裡不搶（Mac 的 Option＋方向鍵是按詞移動／選取），有 ⌘／Ctrl 也不處理。標題列的可及性說明掛在框的 `aria-describedby`。
- **位置**：每個框各記各的（localStorage `agent-board.float.<id>`，讀寫都包 try/catch，讀不到或壞掉就置中）。顯示時一律夾在「頁首下緣以下、視窗以內」（各留 8px），視窗縮小、換螢幕都不會跑到看不到的地方；記住的值不因夾住而改。沒有記錄時置中，右側面板開著且放得下就置中在面板左邊。**回到中間**：雙擊標題列或按標題列的 ⊕（同時清掉記錄）。
- **層級**：`z-index: 35`——在畫布與右側面板（30）之上（從面板打開的框才不會被面板蓋住），在置中次畫面（40）與確認對話框（60）之下。頁首永遠不會被蓋到（位置夾在頁首下緣以下）；和收件匣、團隊面板重疊時框在上面，要操作面板就把框拖開（打開時預設已避開）。同時開兩個以上：最後按過或聚焦的那個在最上面（`.is-front`，36）；第二個以後的框置中時往右下錯開 24px。置中次畫面（設定、搜尋…）或確認框（`.dialog-host`）開著時，浮動框設 `inert`，焦點與點擊不會跑到它身上。
- **鍵盤**：Esc 只在焦點在框裡（不是輸入框）時關框；在輸入框裡按 Esc 不關。焦點不在任何地方時（例如框裡按過的元素被換掉），只有最後按過／聚焦的那一個框會被 Esc 關；點過畫布、面板之後的 Esc 交給畫布與面板，不關框（App 的全域 Esc 也不再關浮動的次畫面）。焦點在任何對話框裡（`[role="dialog"]`、`[data-floating]`，包含框裡的按鈕）時，單鍵全域快捷鍵（N、I、Delete／Backspace 封存選取的卡）一律不觸發。框的根元素帶 `nokey`（置中次畫面的 `.modal-box` 也是）：xyflow 的 Delete／Backspace 不會把框裡的按鍵拿去刪背後選取的交接線。
- **不變的**：網址規則（`#/new`）、上一頁關閉、⌘K 不換掉填到一半的新增表單。
- **草稿**（`shared/draftStore.ts`，只在記憶體，重新整理就沒了）：背後可以操作，就可能點到會換網址的東西（收件匣、團隊框、卡片選單的對話紀錄／交叉審查、全尺寸終端機…），表單會被卸載。新增 session 與新增團隊的欄位放在草稿裡，再打開時還原，跨 640px 換畫法（浮動框 ↔ 手機內嵌）也還原。新增 session：✕、框裡的 Esc、手機「← 返回」是明確關閉，清掉草稿；換網址離開、瀏覽器上一頁不清；送出成功照舊清掉名稱（其他欄位留著方便連開）。新增團隊：關掉只是藏起來；團隊建好（成功或部分成功）才清。補成員框放在「補成員」區塊外面，收起區塊不會卸載。
- **已知限制**：補成員與 Preset 框跟著右側團隊面板：換掉面板（例如點收件匣）時框會關、內容不保留（和改成浮動前內嵌在面板裡一樣）。Preset 框的選擇（清單／預覽）也不放草稿。
- **手機（≤ 640px）**：不浮動。新增 session 維持全螢幕頁、新增團隊／補成員／從 Preset 建立維持內嵌在全螢幕頁裡。比手機寬的觸控裝置（平板）照樣浮動，用手指拖標題列。標題列的按鈕是精簡 32（觸控裝置自動 44，controls.css）。
- **長相**：`--bg` 底、1px `--border-2` 框、圓角 `--radius-card`、`--shadow-modal`；標題列 `--surface` 底＋下框線、標題 14px／650、右側「⊕ 回到中間」「✕」兩顆 `.sm`。新增 session 寬 900，團隊類 480（內容單欄，和團隊面板一致）。高度隨內容，最高到視窗扣頁首，內容自己捲動。

| 允許一次 | Allow once | 允許並記住 | Always allow |
| 拒絕 | Deny | 要求修改 | Request changes |
| 批准計畫 | Approve plan | 交接 | Hand off |
| 上線 | Online | 失聯 | Offline |
| 耗額度 | Uses quota | 略過權限 | Bypass permissions |

- 按鈕寫動詞，不寫「確定」。錯誤寫「發生什麼＋怎麼辦」：「連不到 demo-studio，恢復後會自動接回」。
- 時間寫相對值（「等了 12 分」），提示框顯示完整時間。
- `session`、`worktree`、`hook` 這類專有名詞中文介面也不翻。
