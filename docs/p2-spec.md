## 1. 項目一：分頁改疊加面板

**目標：** 畫布永遠在底下不被卸載，收件匣、團隊、設定都是疊在畫布上的次畫面，且所有舊網址仍可深連結。

### 1.1 使用者故事

- GM 在電腦上看畫布，按「收件匣」從右邊滑出抽屜，逐項處理，處理完收回，畫布縮放位置和終端機都沒變。
- GM 在 iPhone 收到 PERM 推播，點開直接看到那個 session 的審核項目，按允許。
- GM 點畫布上某個團隊框，右側滑出該團隊面板，同時還能拖畫布、點別的卡。
- GM 按右上齒輪，畫面中央出現設定視窗，關掉回到原本畫布。

### 1.2 畫面與互動（桌面 > 640px）

**頁首**：拿掉分頁列（`TABS`）。保留：品牌、「等你 N」、「下一個等我的 N」、機器／用量、遮蔽晶片、語言、**收件匣鈕（帶等你數）**、**齒輪**。「新增 session」在項目三的底部指令列上線前留在頁首，上線後移走。項目二的工作區分頁放在原分頁列的位置。

**三種疊加層**

| 層         | 位置與尺寸                                                                     | 模態                       | 開啟                                                   | 關閉                                             |
| ---------- | ------------------------------------------------------------------------------ | -------------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| 收件匣抽屜 | 右側，寬 480px，可切「展開」760px（看 diff 用），高＝頁首以下全高              | 非模態：畫布仍可拖、可點卡 | 頁首收件匣鈕、點「等你 N」、快捷鍵 `I`、網址 `#/inbox` | 抽屜上的 ✕、`Esc`、再按一次 `I`                  |
| 團隊面板   | 右側，寬 420px（細節見項目二）                                                 | 非模態                     | 點團隊框標籤或框內空白處、網址 `#/team/<id>`           | ✕、`Esc`、點畫布空白處**不**關（避免拖畫布誤關） |
| 設定次畫面 | 置中，寬 min(960px, 視窗 − 96px)、高 min(85vh, 視窗 − 96px)，背後畫布 60% 暗化 | 模態：焦點鎖在視窗內       | 齒輪、網址 `#/settings[/分類]`、`#/archive`            | ✕、`Esc`、點暗化背景                             |

- 右側一次只開一個（收件匣與團隊面板互斥，開一個自動收另一個）。設定可疊在右側面板之上，關設定後右側面板還在。
- `Esc` 只關最上層；**焦點在終端機（xterm）、輸入框、textarea 時，`Esc` 一律交給它，不關面板**（Esc 在終端機是中斷 Claude，不能被吃掉）。`I` 同理在打字時不觸發。
- 動畫 ≤ 200ms，`prefers-reduced-motion` 時無動畫。
- 面板開著時「下一個等我的」照常運作：聚焦卡片，若該項也在收件匣則同步高亮。

**收件匣（待處理＋審核中心合併）**

- 內容＝目前「待處理」與「審核中心」的聯集：只列算「等你」的（ASK、PERM、PLAN、ERR），NEW 不列。每列：狀態燈（符號＋代碼）→ 完整呼號（不截斷）→ 等待時間 → 要做的事。
- 列上可直接做的：允許一次／允許並記住／拒絕＋原因（PERM）、批准計畫／要求修改（PLAN）、回覆（ASK）、查看（ERR）。現有 `ReviewPage` 的審核卡（diff、指令全文、⛔ 危險指令兩次確認、原因必填）原樣搬進來，點列展開。
- 排序：見 §7 問題 Q1。在 GM 回覆前，實作預設「依急迫」（⛔ → ERR → PERM → PLAN／ASK，同級等最久的在前，和 N 鍵一致），並提供分段切換「依急迫｜依組別」，選擇存在本機。
- 每列有「在畫布上看」：聚焦該卡（若在別的工作區則先切工作區，見項目二），抽屜不關。
- 空狀態：「沒有等你的」＋下一步提示。hub 斷線：整個抽屜淡化＋一行字（STYLE 邏輯 8）。

### 1.3 畫面與互動（手機 ≤ 640px）

- 預設首頁維持 `#/inbox`，收件匣**全螢幕**（不是抽屜），列與按鈕沿用現在 `InboxPage` 的手機版（按鈕 ≥ 56px、呼號不省略）。
- 團隊面板、設定在手機都是全螢幕頁，左上「← 返回」回上一個畫面。
- 手機仍可進 `#/canvas`（不禁止），但不是預設。

### 1.4 網址（深連結）規則

| 網址                              | 桌面行為                                                                                                                          | 手機行為       |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `#/canvas`                        | 只有畫布                                                                                                                          | 畫布           |
| `#/inbox`                         | 畫布＋收件匣抽屜                                                                                                                  | 全螢幕收件匣   |

| `#/new`                           | 畫布＋置中完整新增表單（同設定的模態尺寸）                                                                                        | 全螢幕         |

- 開面板＝推一筆歷史；瀏覽器「上一頁」關面板回 `#/canvas`；關面板若上一筆就是 `#/canvas` 用 `history.back()`，否則 `replace` 成 `#/canvas`（避免「上一頁」跳出 app）。
- `sw.js` 的 `inboxUrl` 與 `agent-board.open` 訊息格式**不改**；頁面收到訊息改 hash 時，收件匣已開著也要捲到新的那一項。

### 1.5 資料模型／API

- 無 schema 變更，無 API 變更。純前端。
- 會動到 Lead 專屬的 `App.tsx`（路由要從「換頁」改成「畫布常駐＋疊加層」），派工時要指定 Lead 做或先取得 Lead 同意。

### 1.6 驗收條件（可寫成 e2e）

1. 桌面開 `#/canvas`，把畫布平移縮放到某位置，開收件匣、團隊面板、設定再逐一關掉：視窗 viewport（x、y、zoom）完全相同；終端機卡沒有重新連線（`terminal.subscribe` 不重送）。
2. 桌面直接開 `#/inbox/<id>`（該 session 為 PERM）：畫布在底、抽屜開著、該項展開並有高亮；按「允許一次」後該項消失，抽屜仍開。
3. 手機尺寸（390×844）開 `#/inbox/<id>`：全螢幕收件匣、該項在可視範圍內。
4. 頁面已開在 `#/canvas`，模擬 service worker 送 `agent-board.open`（url 帶 `#/inbox/<id>`）：抽屜打開並捲到該項，頁面沒有重新載入。
5. `#/queue`、`#/review/<id>` 會被轉成 `#/inbox`、`#/inbox/<id>`，且「上一頁」不會回到舊網址造成迴圈。
6. 焦點在終端機時按 `Esc`：抽屜不關，終端機收到 `\x1b`（或 `terminal.signal escape`）。焦點不在輸入元件時按 `Esc`：關最上層。
7. 收件匣與團隊面板互斥；設定可疊在其上，關設定後右側面板仍在。
8. 收件匣不出現 NEW；「等你 N」的 N 等於收件匣列數。
9. 頁首沒有分頁列；所有原分頁的功能都還能從面板或網址到達（清單：待處理、審核、團隊清單、團隊詳細、設定各分類、封存、新增 session）。
10. 設定次畫面開著時 Tab 鍵焦點不會跑到背後畫布。
11. 既有 e2e 改寫後全過；`flows-boot` 4 個不變。

### 1.7 不做什麼

- 不改終端機全螢幕頁 `#/terminal/<id>`。
- 不新增指令面板（Raycast 式），不改左側欄（機器／額度／圖例）。
- 不改審核卡本身的邏輯與按鈕（危險指令兩次確認、原因必填照舊）。
- 不改推播內容與 `sw.js` 網址格式。

### 1.8 風險

- **畫布常駐的記憶體與效能**：以前切到別頁會卸載畫布與 xterm；改成常駐後，開設定時背後 13+ 個 xterm 仍在跑。驗收第 1 條要求不重連，但需量測開面板時的捲動流暢度（手動檢查，未驗證）。
- 收件匣 480px 放 diff 會擠，故提供 760px 展開；仍不夠時點「在新頁看」開 `#/terminal/<id>`。
- e2e 123 處 hash 要改，工作量主要在這裡。

### 1.9 工作量：**大**（前端架構＋合併兩頁＋e2e 大量改寫）

## 2. 項目二：工作區＋團隊名單面板

**目標：** 畫布一次只顯示 GM 手動分好的一組團隊，點團隊框能看到名單並一次對整組或單一 agent 下指令。

### 2.1 使用者故事

- GM 建立「交易」「agent-board」兩個工作區，把 6 個交易團隊拖進「交易」，切到「agent-board」時畫布只剩那邊的團隊，交易那邊的 ASK 仍在分頁上以數字提醒。
- GM 點「台股」團隊框，右側列出 5 個 agent：名稱、角色、狀態代碼、等了多久；在底部輸入「先停下，回報目前進度」按 Enter，送給全部 5 個，不跳確認。
- GM 輸入「@審查 這版再看一次」，只送給審查那一個。
- GM 把某成員角色改成「測試」。

### 2.2 名詞

- **工作區**：GM 手動建立的分組，含若干團隊與不屬於任何團隊的單獨 session。全 hub 共用（不分使用者帳號）。至少存在一個，不能刪光。
- 團隊成員所在的工作區**跟著團隊**；單獨 session 有自己的工作區。
- 程式內部命名必須和既有 `layouts.workspace`（版面組）區分，避免混淆（例如新概念用別的識別字，由實作決定）。

### 2.3 畫面與互動（桌面）

**頂部列（原分頁列位置）**：`[專案下拉（見 Q4）] [工作區A 3] [工作區B] [工作區C 1] [+]`

- 每個分頁顯示名稱＋**該工作區「等你」數**（> 0 才顯示，用 `--you` 樣式，和頁首計數同一套定義）。這是避免「agent 停下來等你而你不知道」：被隱藏的工作區有人在等，分頁上一定看得到。
- 選中分頁：白色 2px 底線（STYLE：強調色白）。
- `+`：原地出現名稱輸入框，Enter 建立並切過去。
- 分頁右鍵（觸控：長按）選單：重新命名、刪除。刪除只在工作區裡**沒有團隊也沒有單獨 session** 時可按；否則顯示「先把 N 個團隊、M 個 session 移到別的工作區」。最後一個工作區不能刪。
- 目前工作區存在本機（每台裝置各自記），重新整理後維持。

**把團隊移進工作區**

- 桌面：按住團隊框標籤拖到頂部某個工作區分頁上放開。拖曳中分頁高亮可放置區。（現在團隊框不吃滑鼠，標籤要改成可拖。）
- 替代（也是觸控做法）：團隊面板頂部「工作區：[下拉]」直接改。
- 單獨 session：卡片「⋯」選單加「移到工作區 ▸」。
- 移過去後，該團隊排到目標工作區現有內容的右側空白處（不疊在別的團隊上）；畫面停在原工作區，顯示一行提示「已移到『交易』［前往］」。
- 新建 session：放在目前工作區。MCP `spawn_member` 開的成員：跟呼叫者同工作區（成員加入團隊後跟團隊）。

**畫布只顯示目前工作區**：別的工作區的卡片、團隊框、交接線、便利貼都不畫，也不訂閱它們的終端機串流。切換工作區後自動 fit view；每個工作區記住自己最後的 viewport。「一鍵整理」只整理目前工作區。

**跨工作區的導航**：「下一個等我的」、收件匣「在畫布上看」、`#/team/<id>`、推播連結若目標在別的工作區，自動切過去再聚焦。頁首「等你 N」與收件匣**一律全域**（不分工作區）。收件匣每列呼號後加工作區名稱晶片。

**團隊面板（項目一的右側面板）**


- 每列：狀態燈（符號＋代碼，代碼色）→ agent 名稱（session 名）→ 角色 → 時間（STYLE 規則四的寫法）。點列＝畫布聚焦該卡，面板不關。角色可在列上用下拉改（走既有 `PUT /api/teams/:id/members/:sessionId`）。

- 名單下方的「任務板／交接規則／目標與 context／研究階段／新增成員」是 `TeamWorkbench` 現有區塊，收合呈現，點開在面板內展開；面板可切「展開」寬 760px 看任務板。
- 團隊清單模式（`#/team` 或底部列「群組」）：列出目前工作區的團隊（名稱、成員數、等你數），＋「新增團隊」（既有 `NewTeamForm`）；切換「顯示全部工作區」。

**指令框（群發）**

- 不跳確認（GM 決定）。送出鈕文字即時顯示對象數：「送給 5 個 agent」／「送給 tw-review」。
- `@`：輸入 `@` 出現成員選單（名稱與角色都可搜），可點名多位；有點名時只送給被點名的，送出的文字**拿掉** `@名稱`。點名的名稱不屬於本團隊 → 送出鈕停用並提示。
- 送字規則與現有自動送字相同：**只在對象 `waiting_input`（NEW、ASK）時送**；RUN、PERM、PLAN、ERR、QUOTA、QUE 的對象排隊，等它變回等輸入才送（絕不把字打進權限對話框）；OFF 也排隊；DONE／已封存的略過。
- 送出後名單每列右側顯示這一則的結果：「已送出」「排隊中（等 RUN 結束）」「略過：已結束」，排隊中的可個別「取消」。
- 群發本身照一般指令計費，不加 ◈ 晶片（它看起來就是在下指令，STYLE 規則三之二不適用）。
- 全部暫停（項目三）期間的行為見 Q6。

**角色「測試」**：新增第五種角色，中文「測試」、英文 Tester。hub 行為見 Q5。

### 2.4 畫面與互動（手機）

- 頂部工作區分頁改成單一下拉（「交易 ▾」），選單內每項帶等你數。
- 手機預設是收件匣（全域，不受工作區影響）；工作區只影響手機上的畫布與團隊清單。
- 團隊面板全螢幕：名單＋指令框可用（手機群發是合理情境）；任務板等收合區塊顯示「回電腦處理」連結，不在手機展開。
- 「移到工作區」用團隊面板頂部的下拉，不支援拖曳。

### 2.5 資料模型／API 變更（**需要 schema 變更：v8 → v9，走既有升級前自動備份**）

- **新表「工作區」**：id、名稱、建立時間、排序值。
- **teams** 加「工作區 id」欄（NOT NULL，外鍵）。
- **sessions** 加「工作區 id」欄（單獨 session 用；是團隊成員時以團隊為準，這欄被忽略但保留）。
- **notes**：`workspace` 欄目前全是 `'default'`，改存工作區 id（便利貼屬於建立時的工作區）。
- **layouts 不動**：座標仍存在同一個版面組（`'default'`），工作區只是顯示篩選。好處是不用搬座標，壞處見風險。
- Migration v9：建立一個預設工作區（名稱「主要」，見 Q3），把所有既有團隊、session、便利貼都歸進去。
- 備份：hub 啟動升級時 `db.ts` 會自動寫 `hub.db.bak-<時間>-v8`。上架前另依 HANDOFF 步驟手動備份一次。**降級**：v8 hub 會拒絕 v9 資料庫，回退＝停 hub → 換回 v8 版 → 還原 `-v8` 備份；升級後新增的工作區、角色變更會遺失。
- **protocol（Lead 改）**：
  - `TeamRole` 加 `'tester'`。DB 的 role 是 TEXT 不用 migration，但**必須和 v9 同一版上架**（舊 hub 讀到 `tester` 會 zod 驗證失敗；同版上架時回退一定伴隨還原 v8 備份，就不會有 tester 資料）。
  - `Team`、`Session`、`Note` 帶工作區 id。
  - REST：工作區 列表／建立／改名／刪除（非空回 409 並附團隊數、session 數）；團隊、session 改工作區（可用既有 PATCH 帶欄位）。
  - REST：**群發** `POST /api/teams/:id/broadcast`，body：文字、可選的對象 session id 清單（點名）；回傳每個對象的結果（sent／queued／skipped＋原因）。**必須在 hub 端走 `SafeDelivery`**，不可由瀏覽器逐一送 `terminal.input`（瀏覽器不知道對方是不是在權限對話框）。排隊結果變化經 WS 推給畫面；取消排隊另一個 API。
  - audit_log：每個對象一筆（action 例如 `team.broadcast`，detail 含團隊 id、全文、是否點名）。
- WS：工作區建立／改名／刪除、團隊與 session 換工作區要即時推給所有 client。

### 2.6 驗收條件

1. 全新 v8 資料庫（含 6 團隊、13 session、2 便利貼）升級到 v9：產生 `-v8` 備份檔；只有一個工作區「主要」；所有團隊、session、便利貼都在裡面；畫布看起來和升級前完全一樣（座標相同）。
2. 建立工作區 B，把團隊 X 的標籤拖到分頁 B 上：X 從目前畫布消失；切到 B 看得到 X 與其所有成員卡、X 內的交接線；X 沒有和 B 原有團隊重疊。
3. 觸控模擬：在團隊面板用下拉把團隊移到 B，結果同上。
4. 工作區 B 內某 session 變 ASK，停在工作區 A：分頁 B 顯示「1」；頁首「等你」含它；按 N 會切到 B 並聚焦它。
5. 切到 A 時，不在 A 的 session 沒有 `terminal.subscribe`。
6. 刪除非空工作區：按鈕停用並顯示數量；清空後可刪；最後一個不能刪。
7. 點團隊框：右側出現面板，名單列數＝成員數，每列狀態代碼與卡片上的 `data-code` 一致。
8. 群發給 4 個成員（ASK、RUN、PERM、NEW 各一）：沒有確認對話框；ASK、NEW 立刻送出；RUN 顯示排隊中，變成 ASK 後才送；PERM 在權限處理前**不送任何字元**；audit_log 多 4 筆（送出時才寫，或排隊時就寫，見實作備註）。
9. `@tw-review 再看一次`：只有 tw-review 收到，收到的文字是「再看一次」。
10. 角色改成「測試」後重新整理仍是測試；MCP `spawn_member` 能指定 tester（若 Q5 決定要）。
11. 降級演練：v9 資料庫在 v8 hub 啟動 → 拒絕並指出 `-v8` 備份位置（沿用 `tooNewMessage`）。
12. 手機尺寸：工作區是下拉、帶等你數；團隊面板全螢幕可群發。

### 2.7 不做什麼

- 不做工作區分頁拖曳排序（先依建立順序）、不做工作區顏色。
- 不做每個工作區各自的「全部暫停」。
- 不做 agent 短名稱＋實例編號、不做依角色分組顯示「完成數／總數」（派工單 §7 工作區小節第 3 點，留到 P3 或之後）。
- 不做 Presets（P3）。
- 不讓工作區影響通知、收件匣與「等你」計數（一律全域）。
- 不改 Claude 的權限、交接、任務自動執行規則本身。

### 2.8 風險

- **座標共用**：不同工作區的團隊可能座標重疊（看不到所以無害），但把團隊移回原工作區時可能壓到別人，所以「移入時排到右側空白」是必要規則。
- **群發排隊在記憶體**：`SafeDelivery` 佇列 hub 重啟會遺失；重啟後排隊中的群發要在畫面上標成「沒送出（hub 重啟）」，不可默默消失。
- 測試角色若預設可寫檔，會增加同 repo 多人改檔衝突（見 Q5）。
- 群發不確認＋排隊：GM 送完忘記，RUN 結束後才送出，可能已不合時宜；排隊中狀態一定要看得到、能取消。

### 2.9 工作量：**大**（schema＋protocol＋hub 群發＋前端兩個新元件）

## 3. 項目三：全部暫停＋底部浮動指令列

**目標：** 一鍵擋下所有自動送字與新開工（可選擇同時中斷正在跑的），並把全域按鈕集中到畫布底部。

### 3.1 使用者故事

- GM 早上出門前按「全部暫停 ▸ 做完這輪就停」：正在跑的那輪跑完，之後交接、任務、派工、自動接續都不再送字，也不會自動開新 session。
- 額度快見底，GM 按「全部暫停 ▸ 立刻中斷」：所有 RUN 立刻收到 Esc，而且之後也不會再被自動餵指令。
- 回來後按「全部繼續」，畫面先告訴他會放出幾則排隊中的東西。

### 3.2 兩種暫停的定義

|                                                                                 | (a) 做完這輪就停 | (b) 立刻中斷                                                  |
| ------------------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------- |
| 擋自動送字（交接、任務自動執行、MCP 派工送工作與回報結果、額度恢復自動接續）    | 擋               | 擋                                                            |
| 擋自動開新 session（QUE 排隊中的 session 有空位時自動啟動、MCP `spawn_member`） | 擋               | 擋                                                            |
| 正在跑的回合                                                                    | 讓它跑完         | 對每個 **RUN** session 送一次 Esc（`terminal.signal escape`） |
| PERM、PLAN、ASK、ERR 的 session                                                 | 不動             | 不動（Esc 在 PERM 會變成拒絕，所以只送 RUN）                  |

- **(b) 一定包含 (a)**：Esc 後 session 變回等輸入，若不擋自動送字，交接／任務會立刻再餵它，等於沒停。
- 被擋下的自動送字**留在佇列**不丟掉，`MCP spawn_member` 回傳錯誤給呼叫的 Claude（訊息說明「board 已暫停」），QUE session 維持排隊。
- GM 自己的手動輸入（卡片指令框、終端機、收件匣回覆、核准）**不受影響**；群發見 Q6。
- 暫停狀態存在 hub（重啟後仍是暫停），所有 client 即時同步，手機也看得到。
- 範圍：所有機器、所有工作區。離線機器上的 RUN（實際上是 OFF）不送 Esc，結果回報中列為「沒送到：失聯」。

**全部繼續**：解除暫停。按下前在按鈕旁顯示「會放出：排隊送字 N 則、排隊 session M 個、到期的自動接續 K 個」（數字為 0 時不顯示該項）。**不會**對被 Esc 中斷的 session 自動送「繼續」（見 Q8）。

### 3.3 畫面與互動（桌面）

**底部浮動指令列**（畫布底部置中，半透明＋模糊，不擋小地圖）：
`[＋ 新增 session] [群組] │ [⏸ 全部暫停 ▾] [▶ 全部繼續]`

- 新增 session：開快速建立（現有 `openQuickCreate`）；按住 Shift 或從選單選「完整表單」開 `#/new` 模態。之後頁首不再有新增鈕。
- 群組：開團隊面板的清單模式（項目二）。項目二未完成前開 `#/team`。
- 全部暫停 ▾：兩個選項，(a)「做完這輪就停」、(b)「立刻中斷全部（Esc）」。(b) 依 STYLE 邏輯 6「危險操作要多一道」按兩次：第一次按鈕變成「再按一次：中斷 N 個 RUN」，3 秒內再按才執行（見 Q7）。
- 暫停中：「全部暫停」鈕變成按下狀態並顯示模式；「全部繼續」才可按。畫布頂部一條提示列：「⏸ 已暫停（做完這輪就停）・排隊 N 則・14:02 起　［全部繼續］」。提示列用中性色（白／灰），**不用狀態色**。
- (b) 執行後結果緊貼按鈕顯示（STYLE 邏輯 7）：「已中斷 7 個；1 個失聯沒送到」。
- 快捷鍵：無（避免誤觸）。
- Presets、Memory：P3。建議本輪**不顯示**（見 Q9）。

### 3.4 畫面與互動（手機）

- 收件匣頂部有暫停狀態列與兩顆按鈕（暫停 ▾、繼續），按鈕 ≥ 56px。手機沒有底部指令列。
- 這是手機上唯一會影響全部 session 的按鈕；(b) 同樣按兩次。

### 3.5 資料模型／API 變更

- **不需要 schema 變更**：暫停狀態用既有 `settings` key/value 表存一個鍵（模式、開始時間、操作者）。
- protocol（Lead 改）：
  - REST `POST /api/board/pause`（body：模式 `finish_turn` | `interrupt`）→ 回傳暫停狀態與 (b) 的中斷結果（每個 session：sent／offline）。
  - REST `POST /api/board/resume` → 回傳放出的數量。
  - REST `GET` 暫停狀態＋排隊統計（或併進 `board.state`）。
  - 權限：user（不是 owner），手機登入的帳號 `GML` 也要能用。
  - WS：暫停狀態變化推給所有 client。
- hub：所有自動送字都已集中在 `SafeDelivery`，暫停時它只收不送；QUE 啟動、`spawn_member`、自動接續的觸發點各自檢查暫停。
- audit_log：`board.pause`（含模式與中斷了哪些 session）、`board.resume`（含放出數量）。每個被 Esc 的 session 另照現有 `terminal.signal` 寫一筆。

### 3.6 驗收條件

1. 暫停 (a) 時，有一條已啟用的交接規則，來源 session 回合結束：目標**沒有**收到字；排隊數 +1；繼續後才送出。
2. 暫停 (a) 時，任務自動執行開著的團隊有任務進行中：負責人變等輸入後不送任務。
3. 暫停 (a) 時，MCP `spawn_member` 回錯誤，不建立 session；QUE session 有空位也不啟動。
4. 暫停 (a) 時，RUN 的 session 繼續跑到回合結束（沒有收到 Esc）。
5. 暫停 (b)：第一次按不執行、第二次才執行；所有 RUN 收到 Esc，PERM／ASK 沒有收到任何輸入；結果訊息數字正確；audit 有一筆 `board.pause` 與每個 session 的 `terminal.signal`。
6. 暫停中 GM 在卡片指令框輸入並送出：正常送達。
7. hub 重啟後仍是暫停；（排隊在記憶體的會遺失，畫面上該數字歸零並在提示列註明「hub 重啟，N 則排隊已清除」— 或依實作備註的替代做法）。
8. 兩個瀏覽器同時開，一邊暫停，另一邊 1 秒內顯示暫停狀態。
9. 手機尺寸收件匣看得到暫停狀態列，可暫停、繼續。
10. 未暫停時底部列「全部繼續」停用；暫停時「全部暫停」顯示目前模式。

### 3.7 不做什麼

- 不做單一工作區／單一團隊暫停。
- 不做排程暫停（例如每天 9:00 自動暫停）。
- 不改 Claude Code 本身（沒有真正的「暫停程序」，Esc 就是中斷回合）。
- 不做 Presets、Memory 的功能。
- 不做 Raycast 式指令面板。

### 3.8 風險

- **Esc 的時機**：hub 看到的 RUN 可能已經在轉 PERM 的瞬間，Esc 會變成拒絕那個權限。緩解：送 Esc 前在 daemon 端再確認一次狀態（和 `SafeDelivery` 送 Enter 前再確認同一個原則）。
- 繼續時一次放出大量排隊送字，可能同時燒很多額度——所以繼續前要顯示數量。
- `SafeDelivery` 佇列只在記憶體：暫停期間 hub 重啟，被擋的交接就沒了。這不是新問題，但暫停讓它更容易發生（暫停時間長）。

### 3.9 工作量：**中**（hub 閘門＋兩個 API＋底部列＋狀態列；hub 端可與項目一並行）

## 4. 項目四：團隊框質感＋拖線把手平常隱藏

**目標：** 團隊框看起來像一塊玻璃底座而不搶狀態色，拖線把手只在需要時出現。

### 4.1 使用者故事

- GM 縮小看整片畫布，團隊框是安靜的毛玻璃底，最亮的仍是在等他的卡。
- 滑鼠移到卡上才看到左右的連接點，可以拖線建交接；平常不會壓到卡片標題。
- 在 iPad 上也能建交接線。

### 4.2 畫面與互動

**團隊框**

- 圓角 16px（以螢幕像素計，隨縮放換算，和現有 `calc(…/var(--z))` 做法一致）。
- 內底：透明深色底（約 `--surface` 4–6% 不透明度）＋背景模糊（毛玻璃）。
- 邊框：1px 團隊色；外側一圈**靜態**柔光（光暈不呼吸、不閃，以免和「等你」卡的呼吸光圈混淆）。光暈用中性白低透明度，團隊色只在 1px 線與標籤（見 Q10）。
- 柔和陰影讓框與畫布分層。
- 標籤：維持左上名稱標籤（不只靠顏色），改成玻璃膠囊；整理鈕留在標籤旁。
- **Liquid Glass 只用在底色與質感**：不新增任何琥珀、青色的裝飾（邊、光、漸層），避免和 ASK 黃、PLAN 青混淆。整個框不得出現狀態色。
- 團隊之間的間距：一鍵整理時加大（數值由實作決定，至少 48px 螢幕像素）。
- `prefers-reduced-transparency`（或效能不足時）退回現在的 1px 框＋8% 底。
- 為了項目二「點團隊框開面板」，框要變成可點，但**拖畫布必須仍能穿過框**：只有標籤與框的邊緣帶可點，或點擊（沒有拖動）才算開面板，拖動照樣平移畫布。

**拖線把手（session 卡左右的 `.ab-handle`）**

- 平常完全隱藏（不佔版面、不顯示）。
- 滑鼠移入卡片（或卡片取得鍵盤焦點）時淡入顯示該卡的兩個把手。
- 開始拖線後，**所有可放置的卡**的目標把手都顯示，放開後恢復隱藏。
- 觸控裝置（沒有 hover 的裝置）：把手一律隱藏；卡片「⋯」選單加「建立交接線…」→ 進入選目標模式（畫布頂部提示「點要交接給誰的卡片；Esc 或 ✕ 取消」），點另一張卡＝建立規則（同 `onConnect`：預設關、不同團隊時顯示同樣的錯誤），點空白處或 ✕ 取消。
- 這個「建立交接線…」選單項目桌面也有（滑鼠不好拖時的替代、鍵盤可達）。

### 4.3 資料模型／API

- 無。純前端（`canvas/TeamFrames.tsx`、`canvas/SessionNode.tsx`、`canvas/canvas.css`、`canvas/CardMenu.tsx`）。

### 4.4 驗收條件

1. 滑鼠不在卡上時，`.ab-handle` 計算後不可見（`opacity: 0` 或 `visibility: hidden`）；移入卡片後可見。
2. 從 A 卡右把手拖到 B 卡：拖曳中 B 的目標把手可見；放開後建立一條關閉中的交接線（行為同現在）。
3. 觸控模擬（`hasTouch`、無 hover）：卡片選單「建立交接線…」→ 點 B 卡 → 建立交接線；點空白取消不建立。
4. 鍵盤：Tab 到卡片時把手可見；選單項目可用鍵盤完成建立。
5. 團隊框有背景模糊與圓角；DOM 掃描團隊框相關樣式不含 `--you`、`--c-ask`、`--c-plan` 或任何 `--c-*` 狀態色。
6. 在團隊框內拖動畫布：畫布平移、不開面板；在框標籤上點一下：開團隊面板（項目二完成後）。
7. 模擬 `prefers-reduced-transparency: reduce`：沒有背景模糊。
8. 手動檢查（記錄數字）：6 團隊、13+ 卡在 Mac mini Safari 與 iPhone 上平移、縮放不明顯卡頓；若卡頓，縮放／平移進行中暫時拿掉模糊。

### 4.5 不做什麼

- 不改團隊色 8 色本身（是否停用冰、沙見 Q10）。
- 不改交接線樣式（弧線化不在本輪）。
- 不改卡片本身的狀態框與呼吸光圈。

### 4.6 風險

- **效能**：大面積 `backdrop-filter` 疊在多個 xterm 後面，縮放時可能掉幀，iPhone 尤其。驗收 8 是手動檢查，未驗證。
- 團隊色中 冰 `#75e5f0` 接近 PLAN 青 `#3dd5e0`、沙 `#f4ec9a` 接近 ASK 黃 `#ffe14d`、杏接近琥珀；邊框加上光暈後更容易被看成狀態（見 Q10）。
- 把手隱藏後 React Flow 的放置判定仍要能命中（隱藏不能是 `display:none` 讓放置失效）。

### 4.7 工作量：**小～中**（純 CSS＋一個選單流程＋效能檢查）

## 5. 相依性與建議實作順序

```
④ 質感＋把手（獨立）
① 疊加面板 ──┬──> ② 工作區＋團隊面板 ──> ③ 底部指令列（前端）
③ 暫停（hub 閘門＋API）──┘（可與 ① 並行）
```

- **① 先於 ②**：團隊面板是 ① 的右側面板之一；工作區分頁放在 ① 拿掉分頁列後的位置；「跨工作區聚焦」要靠 ① 的畫布常駐。反過來先做工作區，會在要被拆掉的分頁架構上多做一次。
- **③ 的 hub 部分不依賴任何項目**，可與 ① 並行；③ 的底部列要等 ①（新增 session 從頁首移走、模態 `#/new`）與 ②（「群組」開團隊清單）。若 ② 延後，「群組」先開 `#/team`。
- **④ 獨立**；但「點團隊框開面板」的可點區域屬於 ②，④ 只負責外觀與不擋拖曳。
- ② 的群發與 ③ 的暫停互相影響（Q6），② 的 hub 群發要用 ③ 的閘門判斷，所以 ③ hub 部分最好在 ② hub 部分之前合併。

**建議順序**

1. ④ 團隊框質感＋把手隱藏（小，先做；順便量出毛玻璃在 iPhone 的效能，影響後面面板要不要也用模糊）。
2. ① 疊加面板（大，Lead 改 `App.tsx`）‖ 同時 ③-hub：暫停閘門、pause／resume API、audit。
3. ② 工作區＋團隊面板（大，schema v9；上架前照 HANDOFF 備份 `hub.db`，畫布外終端機部署）。
4. ③-前端：底部指令列、暫停狀態列、手機收件匣的暫停鈕。

每一步各自一個分支、各自上架，不要四項一起上。②上架是本輪唯一一次 schema 升級。
